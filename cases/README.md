## 三种用法

| 用法 | 做法 |
| --- | --- |
| 课堂演练 | 教师演示关键路径，学生限时独立完成，下课前互评一轮 |
| 课后拓展 | 只给需求与验收标准，不给步骤，自行查阅官方文档完成 |
| 加分任务 | 开放需求，评分看方案取舍与代码质量，不看功能数量 |

## 提交要求

每个案例一个目录，目录内至少包含：

```
cases/case-XX-name/
├── README.md      需求描述、验收标准、运行方式
├── src/           源码
└── notes.md       实现说明：关键决策、遇到的问题、与参考实现的差异
```

`notes.md` 记录思考过程而非代码复述。使用 AI 工具生成的代码，把“提了什么要求、生成了什么、自己改了什么”一并写进去。

所有案例提交到本仓库，提交记录计入过程性考核。
