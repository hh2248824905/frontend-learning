# 单元 3 · 工程规范、质量保障与 Git 协作

第 3 周。产出：带校验钩子的工程模板、一个合并请求 + 一条流水线。

## 本次任务

- [ ] 配 ESLint + Prettier，统一缩进、引号、分号；解决两者规则冲突
- [ ] 配 Stylelint，约束样式文件
- [ ] 用 Husky + lint-staged 加 `pre-commit` 钩子：检查不过不许提交
- [ ] 写流水线配置：提交与合并请求时自动跑 lint 与 build
- [ ] 走一遍完整协作流程：开功能分支 → 提交 → 发起合并请求 → 通过检查 → 合并

## 分支与提交约定

| 分支 | 用途 |
| --- | --- |
| `main` | 稳定分支，只接受通过检查的合并 |
| `feat/u<单元号>-<简述>` | 单个单元或功能的开发分支 |
| `fix/<简述>` | 问题修复分支 |

提交信息按 Conventional Commits 书写，type 取 `feat`、`fix`、`docs`、`style`、`refactor`、`chore`、`test`。

```
feat(u05): 待办清单支持按状态筛选
fix(u02): 修正 vite 代理配置导致的接口 404
docs(u01): 补充环境自检清单
```
