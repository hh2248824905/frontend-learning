# 第一章：前端发展的几个时代

前端从无到有，从附属到独立，再到工程化、跨端、Serverless，经历了 5 个时代。

## 1.1 附属时代

### 1.1.1 前端的诞生

- **1990 年**：世界上第一款浏览器诞生，HTML 作为超文本标记语言用于在网页中展示文字（实验室产品）。
- **1994 年**：网景公司成立，开发了 Navigator 浏览器，HTML 技术得到推广。
- **1995 年**：网景工程师 Brendan Eich 花 10 天设计出 JavaScript（JS），并将其内嵌到浏览器。
- 微软推出 IE 浏览器及 JScript 脚本语言，引发第一次浏览器大战。
- 网景公司将 JavaScript 提交到 ECMA 标准化，形成 **ECMAScript 1.0** 标准。
- W3C + ECMA 两大组织推动 Web 发展。
- **Web 1.0 时代**：纯静态网页、只读、无前后端之分。
- ASP、JSP、PHP 等动态页面技术诞生后，网站开发逐渐被划分为**前端**（HTML/CSS 排版）和**后端**（业务逻辑）。
- MVC 框架下，前端页面作为视图（View）由后端嵌套模板管理，前端开发者被戏称"页面仔""切图仔"。
- 移动互联网 + HTML5 推动前端进入爆发期。

### 1.1.2 jQuery 实现交互

- 早期复杂页面需要大量 DOM 操作，原生 JavaScript DOM API 存在两大问题：
  1. 不同浏览器的 API 存在兼容性；
  2. 原生 API 使用繁琐，没有"链式"和"批量"快捷操作。
- **jQuery 登场**：提供极简 API、链式调用、批量操作，效率至少提升 1 倍。
- jQuery **插件系统**非常强大，是最早意义上的组件化。

## 1.2 分家时代

### 1.2.1 AJAX 出现

- **2005 年**：JavaScript 历史上具有里程碑意义的大事——**AJAX 出现**，带来异步获取数据能力。
- 表单异步提交、提升用户体验、博客论坛评论区促进 **Web 2.0 时代**发展。
- 谷歌 **Gmail** 和 **GoogleMap** 重量级产品展示了 AJAX 的潜力。
- 一体开发的弊端：
  1. **模块划分难**：视图代码前后端混合，难以解耦；
  2. **多人协作难**：在同一仓库拉取合并易冲突。

### 1.2.2 前后端分离

- 全部采用 AJAX 与后端交换数据，理论上可行，但有两个难点：
  1. **路由问题**：AJAX 局部更新不改变 URL，刷新会回到起点；
  2. **状态问题**：纯前端环境无状态，Session 难以处理。
- 此时 AJAX 仍是优化角色，前端正处于黎明前的混沌。

### 1.2.3 三大框架出现并流行

- **2009 年**：谷歌发布 **AngularJS**——引入 MVC、依赖注入、模块化、**双向数据绑定**（最早的数据驱动视图）。
- **2013 年**：Facebook 推出 **React**——虚拟 DOM（Virtual DOM）、JSX 语法、Diff 算法。
- **2014 年**：尤雨溪发布 **Vue.js**——保留双向绑定 + 虚拟 DOM，API 设计简单，中文文档友好。
- 三大框架互相学习、互相竞争，彻底改变了前端的开发方式，进入完全的前后端分离模式，前端正式进化为前端应用。

## 1.3 工程化时代

### 1.3.1 Node.js 开启了前端工程

- **2009 年**：Node.js 诞生，基于 Chrome V8 引擎、单线程、事件循环、异步 I/O。
- **亮点**：
  - JavaScript 语法可开发后端；
  - **Npm 包管理**：数百万免费第三方包；
  - 代码极简、维护简单。
- Node.js 提供**文件操作能力**（浏览器沙盒没有），是前端工程化的萌芽。
- **2015 年**：Angular 团队推出 Angular CLI 脚手架工具，前端工程化开端。
- 脚手架项目自带**热更新**功能（WebSocket 检测文件变化触发编译更新）。

### 1.3.2 Webpack 带来了编译

- **Webpack**：现代 JavaScript 应用程序的打包器，核心作用有两大方面：
  1. **打包**：将任意文件模块化，通过 import/export 实现文件导入导出；
  2. **转换**：通过自定义 **Loader** 处理 Webpack 不认识的非 JS 文件。
- 例如：Vue 的 `.vue` 文件通过 **vue-loader** 转换为 HTML、CSS、JS。
- 编译带来"源码"与"可执行代码"的区别（jQuery 时代没有这个概念）。

### 1.3.3 工程化体系持续完善

优秀工具链集成到工程化体系：

| 工具 | 职责 |
|------|------|
| **Babel** | 将最新 JS 语法转换成 ES5，兼容绝大部分浏览器 |
| **Less/Sass** | 解决纯 CSS 不够友好的问题，支持嵌套、变量 |
| **ESLint** | 检测代码规范，统一团队编码风格 |

> 后期衍生技术：持续集成、CI/CD、自动化部署等。

## 1.4 大前端时代

### 1.4.1 多端开发的现状

- 移动互联网兴起：PC 端 + 移动端 H5。
- 客户端：Android、iOS，与前端完全不同。
- **小程序**：内嵌在 App 中以微应用方式打开，使用 JavaScript 开发，效率与前端页面基本一致。
- 各大厂小程序（微信、支付宝、抖音、头条）虽大同小异但**代码互不兼容**。
- 客户端阵营囊括 **Web、原生 App、小程序**三大类，细分至少 5 个客户端，成本高昂。

### 1.4.2 跨端开发成为趋势

- 既然 Webpack/Babel 能将任意高级语法（JSX）转换成 JS，那是否也能生成另一套其他平台的代码？
- 创造性思路：编写转换工具将一套 Vue.js 代码转换为小程序代码，实现"一套代码打包成多个应用"。
- 优秀的跨端解决方案：**UniApp、Taro、React Native、Electron、Flutter**。
- 大前端不是只有跨端，还包括：图形技术、音/视频技术、VR 技术。

### 1.4.3 一处代码，多处运行

1. **UniApp**：以 Vue.js 语法为核心，编译时将 Vue 代码转换成目标平台原生代码，真正"一次编写，多端运行"。
2. **Taro**：使用 React 语法的跨端开发框架。Taro 3 升级为"运行时的自定义渲染"，同时支持 React 和 Vue.js 语法。
3. **React Native**：将 React 代码生成原生 Android、iOS 应用，是 JavaScript 开发原生 App 的主流方案。
4. **Electron**：开发桌面端应用（Windows 和 Mac），VSCode 即用 Electron 开发。内部嵌入 Chromium + Node.js。
5. **Flutter**：Google 推出的移动应用开发框架，主打跨平台、高保真、高性能。使用 Dart 语言，支持 Web、Windows、Mac、iOS、Android、Linux 六大平台。

## 1.5 Serverless 时代

### 1.5.1 函数即服务

- **FaaS（Function as a Service）**：面向函数构建和部署软件的方式，即**云函数**，是 Serverless 的最终表现形式。
- 以前的函数是"本地声明，本地调用"；现在云函数单独部署在云上，供前端远程调用。
- 云函数内部封装了数据库操作，前端开发者直接调用数据库类方法（增、查、改、删），抹掉了接口这一层。
- 大厂探索框架：阿里巴巴 **Midway.js**、字节跳动 **Modern.js**。

### 1.5.2 前后端一体化开发

- FaaS 模式下，前端开发者除了担负传统的界面开发，还要担负数据库管理（编写云函数操作数据）。
- 要求每个前端开发者必须有**全栈开发**的能力。
- 未来 Serverless 普及后，会打破前后端分离，转变为基于 JavaScript 的前后端一体化开发。
- 从 PHP 模板渲染 → 前后端分离 → 前后端一体化，恰好印证"合久必分，分久必合"。
- 前端一步步发展壮大，逐步走到了应用开发的中心。

### 1.6 本章小结

| 时代 | 模式 |
|------|------|
| 附属时代 | MVC 模式下的前端 |
| 分家时代 | 前后端分离模式下的前端 |
| 工程化时代 | 前端工程化的进阶 |
| 大前端时代 | 前端在跨端方向的统一 |
| Serverless 时代 | 面向未来的前后端一体化开发 |

# 第二章：掌握前端"三驾马车"

不管前端发展到哪个时代，根基永远是"三驾马车"——**HTML、CSS、JavaScript**，它们是前端在任何时候都不会过时的基础。

## 2.1 HTML：搭建页面的结构

### 2.1.1 核心 DOM 体系

- **HTML** 是伴随浏览器出现的超文本标记语言，由一系列元素组成。
- HTML 基本结构：

```html
<!DOCTYPE html>
<html>
  <head>
    <!-- 元数据 -->
  </head>
  <body>
    <!-- 可见内容 -->
  </body>
</html>
```

- **DOM（Document Object Model）**：DOM 不仅是一套接口，更是一套 W3C 规范，约束浏览器中 JavaScript 与 HTML 的交互方式。
- DOM 中主要有 4 种类型的节点：
  1. **Document**：整个 DOM 树
  2. **Element**：单个元素
  3. **Text**：元素内的纯文本
  4. **Attribute**：元素的属性

- 节点之间的关系：
  - **父子节点**：节点之间是嵌套关系；
  - **兄弟节点**：节点之间是平级关系。

- DOM API 操作节点：

```javascript
// 获取元素
var div = document.getElementById('div')
var div = document.querySelector('#div')
var div = document.getElementsByTagName('div')[0]

// 修改/删除元素
div.style.width = '300px'
div.innerHTML = '<span>我的 div 的内容</span>'
div.remove()

// 创建元素
var parent = document.getElementById('parent')
var span = document.createElement('span')
parent.appendChild(span)
```

- `<head>` 元素通常包含的 4 个子元素：
  - `<title>`：文档标题
  - `<link>`：引入外部资源（CSS、图标、PWA manifest）
  - `<script>`：引入或执行 JavaScript 脚本
  - `<meta>`：配置元数据（charset、SEO、viewport）

### 2.1.2 语义化元素

- `<body>` 元素中的子元素分为两类：
  - **内容元素**：文字、图片等用于展现内容；
  - **布局元素**：不直接展示内容，而是将内容元素更好地排列布局。

- 早期 `DIV + CSS` 布局的问题：
  - 代码结构混乱，可读性差；
  - 浏览器无法区分，SEO 效果糟糕。

- HTML 5 语义化元素（替代清一色的 `<div>`）：

| 元素 | 含义 |
|------|------|
| `<header>` | 网页的头部区域 |
| `<nav>` | 导航区域 |
| `<section>` | 页面中的一块子区域 |
| `<aside>` | 侧边栏 |
| `<main>` | 页面内容区域 |
| `<article>` | 文章区域 |
| `<footer>` | 网页的尾部区域 |

- 语义化能实现更好的 SEO，因为浏览器解析时可重点抓取 `<header>`、`<nav>` 中的关键字。

### 2.1.3 了解 HTML 5

HTML 5 新特性：
- 增加音频元素 `<audio>` 和视频元素 `<video>`；
- 增加绘画元素 `<canvas>` 和 `<svg>`；
- 增强对表单的支持；
- 引入本地存储机制；
- 支持地理定位和拖放；
- 支持 WebWorkers；
- 支持 WebSocket。

**音/视频元素 3 种**：
- `<audio>`：音频元素；
- `<video>`：视频元素，常用属性：
  - `poster`：视频封面
  - `autoplay`：自动播放
  - `loop`：循环播放
  - `controls`：显示视频控制条
  - `muted`：是否禁音
- `<source>`：包裹在 audio/video 中，指定类型和资源地址。

通过 JavaScript 操作视频示例：

```javascript
const video = document.getElementById('video1')
video.play()
video.pause()
video.currentTime = video.currentTime + 15  // 快进 15 秒
```

### 2.1.4 实现表单与验证

`<input>` 元素的新 type 属性：

```html
<input type="date" />
<input type="time" />
<input type="datetime-local" />
<input type="month" />
<input type="color" />
<input type="number" min="1" max="10" />
<input type="email" />
<input type="range" min="1" max="10" />
```

`<input>` 元素的其他新属性：
- `autofucus`：自动聚焦
- `autocomplete`：自动填充
- `max/min`：最大/最小值
- `maxlength`：最大字符长度
- `disabled`：禁用元素
- `readonly`：元素只读
- `form`：指定所属表单
- `required`：必填
- `pattern`：自定义验证规则
- `novalidate`：提交表单时不验证

**`disabled` 与 `readonly` 的区别**：
1. `disabled` 对所有表单类元素有用，`readonly` 只对文本和密码文本框有用；
2. 设置 `disabled` 后 JavaScript 获取不到目标元素，`readonly` 则可以；
3. 设置 `disabled` 后表单数据不会传输，`readonly` 则依然可以传输；
4. 两者都会使表单验证失效（等价于同时设置了 `novalidate` 属性）。

阻止默认页面刷新：

```html
<form id="form1" onsubmit="onSubmit(this);return false;">
  ...
</form>
```

```javascript
function onSubmit(e) {
  let formData = {}
  Array.from(e.children)
    .filter((el) => el.name)
    .forEach((el) => {
      formData[el.name] = el.value
    })
  console.log(formData)
}
```

## 2.2 CSS：修饰页面的布局和样式

CSS 中文全称"层叠样式表"，专门用来设置样式，核心价值是描述 HTML 元素应如何被浏览器渲染。

CSS 三次大版本迭代：
- **CSS1**：已被废弃；
- **CSS2**：W3C 规范，当前仍是标准；
- **CSS3**：能力强大也最好用，标准仍在制定中。

### 2.2.1 3 种页面布局方案

**1. 浮动布局**

```html
<div id="app">
  <div class="menu">我是菜单</div>
  <div class="content">我是内容</div>
</div>
```

```css
#app .menu {
  width: 200px;
  height: 400px;
  float: left;
  background: pink;
}
#app .content {
  height: 400px;
  background: lightblue;
}
```

> 浮动布局问题：元素浮动后脱离文档流，父元素高度变 0；需用 `clear:both` 清除浮动，并不优雅。

**2. inline-block 布局**

```css
#app .menu {
  display: inline-block;
}
#app .content {
  display: inline-block;
}
```

> 问题：元素之间默认有留白，需用 `letter-spacing: -100px` 处理。

**3. Flex 布局（CSS3 终极方案）**

```css
#app {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

**Flex 三个重要概念**：
- **容器**：将任意元素设置为 `display: flex`；
- **主轴**：默认横向（从左到右）；
- **交叉轴**：与主轴相差 90°。

`flex-direction` 主轴方向：
- `row`：横向从左到右（默认）；
- `row-reverse`：横向从右到左；
- `column`：纵向从上到下；
- `column-reverse`：纵向从下到上。

`justify-content` 主轴对齐方式：
- `flex-start`：从左到右；
- `flex-end`：从右到左；
- `center`：居中对齐；
- `space-between`：两端对齐（元素本身无间距）；
- `space-around`：两端对齐（元素之间间距相同）。

`align-items` 交叉轴对齐方式：
- `flex-start`、`flex-end`、`center`；
- `baseline`：基线对齐；
- `stretch`：填满整个高度（默认）。

`flex-wrap` 换行设置：
- `nowrap`：不换行（默认）；
- `wrap`：换行，第一行在上；
- `wrap-reverse`：换行，第一行在下。

### 2.2.2 样式与动画解析

**1. 渐变（Gradients）**

CSS3 定义了两种类型的渐变：
- **线性渐变（Linear Gradients）**：上下/左右/对角方向改变颜色；
- **径向渐变（Radial Gradients）**：由中心点向外扩散改变颜色。

```css
.box {
  background: linear-gradient(120deg, red, yellow, blue);
}
```

文字渐变（变通方法）：

```css
h1 {
  background: linear-gradient(120deg, red, yellow, blue);
  color: transparent;
  background-clip: text;
  -webkit-background-clip: text;
}
```

**2. 转换（Transform）**

2D 转换函数：

| 函数 | 作用 |
|------|------|
| `translate(x, y)` | 位移 |
| `rotate(0deg)` | 旋转 |
| `scale(x, y)` | 缩放（1 为基准） |
| `skew(x, y)` | 倾斜 |

可拆分为 `translateX()`、`translateY()` 等单独方法。多参数支持：

```css
.box:hover {
  transform: scale(1.2) rotate(30deg);
}
```

**3. 过渡（Transition）**

元素变化时指定一个时间慢慢变化，瞬间改变太生硬。

```css
.box {
  width: 200px;
  height: 200px;
  background-color: lightblue;
  transition: height 1s, transform 1s;
}
.box:hover {
  height: 250px;
  transform: translate(50px) scale(1.1);
}
```

`transition` 简写由 4 个属性组成：
- `transition-property`：指定过渡的 CSS 属性名
- `transition-duration`：指定过渡时间，默认为 0
- `transition-timing-function`：过渡时间的变化速度（linear、ease、ease-in、ease-out、贝塞尔曲线）
- `transition-delay`：过渡何时开始，默认为 0

**4. 动画（Animation）**

过渡是线性行为（A→B），连续动画需要 `@keyframes` + `animation` 属性。

```css
@keyframes myAnimation {
  from {
    transform: rotate(0deg);
  }
  to {
    transform: rotate(360deg);
  }
}
.box {
  animation: myAnimation 12s linear 0s infinite;
}
```

`animation` 简写属性：
- `animation-name`：指定动画名称
- `animation-duration`：指定动画时长
- `animation-timing-function`：指定速度变化曲线
- `animation-delay`：指定延迟时间
- `animation-iteration-count`：指定动画播放次数（如 infinite 无限次）

百分比更细粒度控制动画（如跑马灯）：

```css
@keyframes marquee {
  0%   { transform: translateX(0); }
  25%  { transform: translateX(-25%); }
  ...
}
```

### 2.2.3 CSS 工程化

CSS 工程化代表：**预处理（Less/Sass）+ 后处理（PostCSS）**。

**1. 预处理器：Less/Sass**

普遍特性：
- 具有嵌套代码的能力；
- 支持模块化的引用（`@import`）；
- 支持定义 CSS 变量；
- 允许代码混入；
- 提供计算函数（如 `hsl()`）。

```less
// a.less
@main-color: red;
.a {
  color: @main-color;
}
```

```sass
// b.sass
$main-color: red;
.a {
  color: $main-color;
}
```

**混入（Mixins）**：

```less
.custom-shadow {
  box-shadow: 2px 0px 2px 1px #f3f3f3;
}
.box1 {
  background: red;
  .custom-shadow();
}
```

```sass
@mixin custom-shadow {
  box-shadow: 2px 0px 2px 1px #f3f3f3;
}
.box1 {
  background: red;
  @include custom-shadow;
}
```

Chrome 49 之后 CSS 自定义变量：

```css
:root {
  --main-color: red;
}
.a {
  color: var(--main-color);
}
```

**2. 后处理器：PostCSS**

通过 **autoprefixer** 自动添加浏览器前缀：

```css
.box {
  transition: all 4s ease;
  /* 自动补充 */
  -webkit-transition: all 4s ease;
  -moz-transition: all 4s ease;
  -ms-transition: all 4s ease;
  -o-transition: all 4s ease;
}
```

PostCSS 还支持直接使用未来的 CSS 语法、自动处理 polyfills。

### 2.2.4 动态值与响应式

响应式布局的关键是"动态"，解决 PC 端网页用手机打开样式"乱跑"的问题。

**3 种响应式方案**：
1. **媒体查询**（用 `@media` 设置宽度范围）；
2. **rem**（相对 HTML 根元素 font-size）；
3. **vw / vh + calc() 计算动态尺寸**。

**1. 媒体查询**：

```css
body { font-size: 20px; }
@media screen and (max-width: 850px) {
  body { font-size: 18px; }
}
@media screen and (max-width: 400px) {
  body { font-size: 16px; }
}
```

**2. rem**：

```css
html { font-size: 10px; }
body h2 { font-size: 2rem; }
```

JS 动态调整（兼容性好）：

```javascript
let resizeEvent = 'orientationchange' in window ? 'orientationchange' : 'resize'
const recalc = () => {
  let width = document.body.clientWidth
  document.getElementsByTagName('html')[0].style.fontSize = 14 * (width / 750) + 'px'
}
document.addEventListener('DOMContentLoaded', recalc)
window.addEventListener(resizeEvent, recalc)
```

**3. vw/vh + calc() 纯 CSS 方案**：

```css
.box {
  width: 20vw;   /* 1vw = 浏览器宽度的 1% */
  height: 20vh;  /* 1vh = 浏览器高度的 1% */
}

body { font-size: 0.3vw; }

/* calc() 动态计算 */
.left { width: calc(100vw - 100px - 80px); }
.right { width: 80px; }
```

## 2.3 JavaScript：页面运行的核心原理

JavaScript 的语法虽然在升级，但核心的运行机制并没有改变，依然是单线程基于事件循环执行任务，依然是基于原型的面向对象。

### 2.3.1 数据类型与函数

**存储方式**：
- **基本类型（原始类型）**：结构简单，直接保存在栈内存中；
- **引用类型（复杂类型）**：保存在堆内存中。

**基本类型（6 种）**：

| 类型 | 说明 |
|------|------|
| String | 字符串 |
| Number | 数值 |
| Boolean | 布尔值 |
| Null | 空 |
| Undefined | 未定义 |
| Symbol | 唯一的值（ES6 新增） |

`typeof` 判断基本类型：

```javascript
typeof 'hello'      // "string"
typeof 5             // "number"
typeof false         // "boolean"
typeof console.log   // "function"
typeof {}            // "object"
typeof []            // "object"
typeof null          // "object"（特例）
```

**Null vs Undefined**：
- **Undefined**：声明但未赋值的状态（声明未赋值、访问对象不存在的属性、函数定义了参数但未传参）；
- **Null**：被人为设置为空对象（开发者主动赋值，表示"有值但是空"）。

**引用类型**：Object、Array、Function、Date、RegExp。

判断 Null 与除函数外引用类型用 `Object.prototype.toString()`：

```javascript
Object.prototype.toString.call([])              // [object Array]
Object.prototype.toString.call({})              // [object Object]
Object.prototype.toString.call(null)            // [object Null]
Object.prototype.toString.call('前端')           // [object String]
```

**`instanceof`**：基于原型链判断实例是否继承自某个构造函数。

### 2.3.2 变量与作用域

- `var` 关键字声明的变量的作用域：全局作用域 + 函数作用域。
- 函数内可访问函数外的变量（事件冒泡式查找），函数外不可访问函数内的变量。

ES6 新增**块级作用域**（用 `let` 声明）：

```javascript
{
  let city1 = '上海'   // 块级
  var city2 = '南京'   // 函数/全局
}
console.log(city1)  // ReferenceError
console.log(city2)  // 南京
```

`let` 关键字特性：
- 相同变量名禁止重复声明；
- 不存在变量提升。

**变量提升**：

```javascript
// var 的变量提升
function fun2() {
  console.log(str)
  var str = '前端开发'
}
fun2()  // undefined

// let 不存在变量提升
function fun2() {
  console.log(str)
  let str = '前端开发'
}
fun2()  // ReferenceError
```

**`const` 关键字**：
- 声明常量，声明后不可修改；
- 声明时必须赋值；
- 与 `let` 一样的特性（块级作用域、不提升、不可重复声明）；
- **引用类型的数据本身更改不算重新赋值**（指针不变），重新赋值才会改变指针报错。

> 建议：用 `let + const` 代替 `var` 关键字声明。

### 2.3.3 面向对象

JavaScript 是独有的基于**原型和原型链**实现的面向对象。

**核心概念**：
- **原型（prototype）**：是一个对象（原型对象），用于实现继承和复用；
- 原型对象有 `constructor` 属性，指向构造函数；
- `__proto__` 指向内部属性 `[[Prototype]]`。

3 条核心规律：
1. 构造函数有 `prototype` 属性，指向它的原型对象；
2. 原型对象有 `constructor` 属性，指回构造函数；
3. 实例有 `__proto__` 属性，指向构造函数的原型对象。

第 4 条规律：**原型对象也有 `__proto__` 属性，指向上层原型对象，直到原型对象为 null**。

示例：

```javascript
Array.prototype.constructor === Array   // true
arr.__proto__ === Array.prototype        // true
```

**原型链**：

```javascript
// Array.prototype 本身也是 Object 的实例
// 当在 Array.prototype 上找不到 valueOf()，会沿着 __proto__ 向上找
// 直到 Object.prototype（其 __proto__ === null）
arr.valueOf()   // ['北京']
```

**手动实现原型链继承**：

```javascript
// 定义 MyCat 构造函数
function MyCat(name, color) {
  this.name = name
  this.color = color
}

// 为原型添加方法
MyCat.prototype.call = function () {
  console.log('喵喵喵')
}

var xixi = new MyCat('西西', '白色')
xixi.call()  // 喵喵喵
```

**多层继承（借助构造函数借用）**：

```javascript
function MyPets() {
  this.owner = '小明'
}

function MyCat(name, color) {
  MyPets.call(this)
  this.name = name
  this.color = color
}
MyCat.prototype.__proto__ = MyPets.prototype
```

**ES6 class 语法糖**：

```javascript
class MyPets {
  owner = '小明'
}

class MyCat extends MyPets {
  constructor(name, color) {
    super()
    this.name = name
    this.color = color
  }
  call() {
    console.log('喵喵喵')
  }
}
```

### 2.3.4 事件循环（Event-Loop）

经典异步代码：

```javascript
console.log(1)
setTimeout(function () {
  console.log(2)
})
new Promise(function (resolve) {
  console.log(3)
  resolve()
})
  .then(function () {
    console.log(4)
  })
  .then(function () {
    console.log(5)
  })
console.log(6)
```

**3 个重要角色**：
1. **函数调用栈**：每个代码块会被放到栈中按"后进先出"顺序执行；
2. **宏任务（Macro-Task）队列**：`setTimeout`、`setInterval`、`script` 脚本等；
3. **微任务（Micro-Task）队列**：`Promise.then`、`catch`、`finally` 等。

> `script` 脚本（全局代码）也是一个宏任务；`setImmediate`、`process.nextTick` 是 Node.js 独有。

**打印顺序**：1、3、6、4、5、2

**事件循环流程**：一个宏任务 → 一组微任务 → 一个宏任务 → 一组微任务。

**宏任务和微任务的区别**：
1. 宏任务先执行，第一个宏任务就是全局代码，宏任务与微任务交替执行；
2. 宏任务是一个一个地执行，微任务是一整列一次执行完毕。

### 2.3.5 执行上下文与 this

**执行上下文**主要分为 3 种：
1. **全局上下文**：全局代码所处的环境；
2. **函数上下文**：函数调用时创建的上下文；
3. **Eval 上下文**（几乎已被废弃）。

**执行上下文生命周期**分两个阶段：
- **创建阶段**：初始化变量和函数等；
  1. 创建全局对象（Window 或 Global）；
  2. 创建 this，指向全局对象；
  3. 将变量和函数放到内存中，为变量赋值 undefined；
  4. 创建作用域链。
- **执行阶段**：逐行执行脚本中的代码。

**全局 vs 函数上下文区别**：

| 对比 | 全局上下文 | 函数上下文 |
|------|-----------|-----------|
| 创建时机 | 运行脚本时创建 | 函数调用时创建 |
| 创建频率 | 仅第一次运行时创建一次 | 调用一次创建一次 |
| 创建参数 | 全局对象（Window） | 参数对象（argument） |
| this 指向 | 全局对象 | 取决于函数如何被调用 |

**闭包**：

```javascript
function funOut(a) {
  return function funIn(b) {
    return a + b
  }
}
var funAdd = funOut(10)
console.log(funAdd(20))  // 30
```

> 闭包原理：执行上下文创建阶段创建了**作用域链**，将父级函数上下文中的变量保存下来。函数执行上下文会被销毁，但作用域链会被缓存。

### 3.1.2 对象的扩展

**简化定义**：`key == value` 时可只用一个属性名：

```javascript
var city = '北京市'
var object = { city, getCity() { return city } }
```

**1. 扩展运算符（...）**

```javascript
// 取剩余属性
var obj = { a: 1, b: 2, c: 3, d: 4, e: 5 }
let { a, b, ...other } = obj
// other = { c: 3, d: 4, e: 5 }

// 复制整个对象（浅拷贝）
let copy = { ...obj }
```

**2. 描述对象（Descriptor）**

通过 `Object.getOwnPropertyDescriptor()` 获取描述对象，6 个常用属性：
- `value`：属性值
- `writable`：属性值是否可以修改
- `enumerable`：描述对象是否可以修改
- `get`：取值函数（getter）
- `set`：存值函数（setter）
- `configurable`：目标属性是否可以被删除或修改特性

```javascript

Object.defineProperty(obj, 'city', {
  writable: false,
})
obj.city = '上海'
console.log(obj)  // { city: '北京' }
```

> Vue.js 就是通过 setter 和 getter 实现响应式系统的。

**3. 对象遍历**

3 个便捷方法：
- `Object.keys()`：获取对象的属性数组
- `Object.values()`：获取对象的值数组
- `Object.entries()`：获取对象的属性和值数组

```javascript
var obj = { name: '李小龙', position: '香港', skill: '中国武术' }
Object.keys(obj)     // ['name', 'position', 'skill']
```

**4. 对象拷贝**

```javascript
// 浅拷贝 3 种方式
var b = a                                  // 1. 赋值引用
var b = { ...a }                           // 2. 扩展运算符
var obj = Object.assign({}, obj2, obj3)    // 3. 对象合并

// 深拷贝（JSON）

```

> Object.assign() 是对对象属性的扩增；扩展运算符是对对象属性的缩减。

### 3.1.3 数组的扩展

**1. 数组查询（4 个方法）**

| 方法 | 作用 |
|------|------|
| `find()` | 查找匹配的第一个元素 |
| `findLast()` | 查找匹配的最后一个元素 |
| `findIndex()` | 查找匹配的第一个元素的索引 |
| `findLastIndex()` | 查找匹配的最后一个元素的索引 |

```javascript

  { name: '赛罗', color: '红蓝' },
  { name: '捷德', color: '红黑' },
  { name: '迪迦', color: '红蓝' },
]
arrs.find(row => row.color == '红蓝')        // { name: '赛罗', ... }
arrs.findLast(row => row.color == '红蓝')    // { name: '迪迦', ... }
arrs.findIndex(row => row.color == '红黑')   // 1
```

**2. 数组过滤**

```javascript
// filter() 按条件筛选

// slice() 按下标（左闭右开）

// includes() 判断包含
```

**3. 数组遍历**

**4. 数组转换**

### 3.1.4 函数的扩展

**箭头函数**：

// ES5
function getName(name) {
  return name
}
// ES6 箭头函数（单返回可简写）

**`this` 指向差异**：

### 3.1.5 异步编程方案

```

> 使用 async/await 务必包裹 `try...catch` 语句。

### 3.2.2 Node.js 的内置模块

**2. fs 模块**：文件系统模块

// 异步读取
fs.readFile('/path/test.txt', 'utf-8', (err, data) => {
  console.log(data)
})

// 同步读取
const data = fs.readFileSync('/path/test.txt', 'utf-8')

// 检查文件状态
let stats = fs.statSync('/path/test.txt')
console.log(stats.isFile(), stats.size)
```

**3. http 模块**：创建 HTTP Web 服务器

```javascript
const http = require('http')
const server = http.createServer((request, response) => {
  response.statusCode = 200
  response.setHeader('Content-Type', 'text/plain')
  response.end('hello world')
})
server.listen(3000)

// 请求对象 request
const { method, url, headers } = request
```

> Express 等成熟框架基于 http 模块进行改造。

## 3.3 TypeScript：支持类型的 JavaScript

TypeScript 是 JavaScript 的超集，扩展了类型系统，可以说 TypeScript 是支持静态类型的 JavaScript。

### 3.3.1 应该使用 TypeScript 吗

**1. 静态类型检测**：

```javascript
// JavaScript
var name = '张三'
name = false    // 合法但易出错

// TypeScript
var name: string = '张三'
name = false    // 编译错误：不能将 false 分配给 string 类型
```

**2. 快捷提示**：VSCode 智能提示对象的属性和方法，提高开发效率。

```typescript
interface Person {
  firstName: string
  lastName: string
  age: number
  greet: () => string
}

function createPerson(firstName: string, lastName: string, age: number): Person {
  return {
    firstName,
    lastName,
    age,
    greet() {
      return `Hello, my name is ${this.firstName} ${this.lastName} and I am ${this.age} years old`
    }
  }
}
```

### 3.3.2 常用类型全览

**8 个常用类型**：

| 类型 | 含义 |
|------|------|
| `string` | 字符串 |
| `number` | 数值 |
| `boolean` | 布尔值 |
| `null` | Null |
| `undefined` | Undefined |
| `symbol` | Symbol |
| `type[]` | 数组 |
| `object` | 对象 |

```typescript
var godName: string = '孙悟空'
var godAge: number = 100
var isGod: boolean = true

var age: null = null
var area: undefined = undefined
```

> 在 `tsconfig.json` 的 `compilerOptions` 中添加 `"strictNullChecks": true` 可启用严格 null/undefined 检查。

**数组类型**：

```typescript
let arr1: number[] = [1, 2, 3]
let arr1: (number | string)[] = [1, 2, '3', '4']   // 联合类型
let arr2: any[] = [1, '2', true, null]
```

> 不推荐使用 `any`，会丢失类型验证。

**函数类型**：

```typescript
function fun1(): void { console.log('无返回值') }
function fun3(name: string): string { return `姓名: ${name}` }
const fun4 = (name: string, tag?: string): string => tag || '' + name

// 自定义类型（类型别名）
type myFunType = (name: string, tag?: string) => string
var fun6: myFunType = (name, tag) => name + tag
```

**联合类型 + 类型断言**：

```typescript
var val1: string | number
var val2: object | null = null

// 类型断言
let val4: unknown = 'this is a string'
let strLength: number = (val4 as string).length
```

> 只有非常确定数据类型的情况下才使用类型断言。

### 3.3.3 接口与泛型

**1. 接口（interface）**：

```typescript
interface StudentType {
  id: number
  name: string
  desc?: string    // 可选属性
}

const student: StudentType = {
  id: 1,
  name: '小明',
}

// 多层嵌套接口
interface BaseType {
  value: number
  label: string
}
interface ListType {
  tag: string
  list: BaseType[]
}
```

**2. 泛型（Generics）**：允许创建可重用、类型安全的代码。

**泛型函数**：

```typescript
function identity<T>(arg: T): T {
  return arg
}
let output1 = identity<string>('Hello TypeScript!')
let output2 = identity<number>(42)
```

**泛型接口**：

```typescript
interface Pair<T, U> {
  first: T
  second: U
}
let pair1: Pair<string, number> = { first: 'One', second: 1 }
```

**泛型类**：

```typescript
class GenericNumber<T> {
  zeroValue: T
  add: (x: T, y: T) => T
  constructor(zeroValue: T, addFn: (x: T, y: T) => T) {
    this.zeroValue = zeroValue
    this.add = addFn
  }
}
```

**泛型约束**：

```typescript
interface Lengthwise {
  length: number
}
function logLength<T extends Lengthwise>(arg: T): T {
  console.log(arg.length)
  return arg
}
logLength('Hello')      // 16
logLength([1, 2, 3])    // 3
// logLength(42)        // 错误：number 没有 length 属性
```

**泛型默认类型**：

```typescript
function createArray<T = string>(length: number, value: T): T[] {
  return new Array(length).fill(value)
}
```

> `any` 和泛型的区别：`any` 直接屏蔽类型验证；泛型是类型变量，有严格的类型验证。

### 3.3.4 装饰器

装饰器是 ECMAScript 的提案，没有标准化，在 TypeScript 中也只是试验性功能，需在配置中开启。

**开启装饰器**：`tsconfig.json` 中添加 `"experimentalDecorators": true`。

**1. 类装饰器**：

```typescript
function LogClass(constructor: Function) {
  console.log(`Class ${constructor.name} is being created`)
}

@LogClass
class MyClass {}
// 输出: Class MyClass is being created
```

**2. 方法装饰器**：

```typescript
function LogExecutionTime(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
) {
  const originalMethod = descriptor.value
  descriptor.value = function (...args: any[]) {
    console.log(`Executing ${propertyKey}...`)
    return originalMethod.apply(this, args)
  }
}

class MyService {
  @LogExecutionTime
  doSomething() {
    console.log('Doing something')
  }
}
```

**3. 属性装饰器**：

```typescript
function DefaultValue(value: any) {
  return function (target: any, propertyKey: string) {
    target[propertyKey] = value
  }
}

class TestClass {
  @DefaultValue('Hello, World!')
  greeting: string
}
```

**4. 参数装饰器**：

```typescript
function LogParameter(
  target: any,
  propertyKey: string,
  parameterIndex: number
) {
  console.log(`Parameter at index ${parameterIndex} in method ${propertyKey}`)
}

class DemoClass {
  greet(@LogParameter message: string) {
    console.log(message)
  }
}
```

> 装饰器应用场景：日志记录、权限控制、依赖注入、数据验证。但需谨慎使用，避免滥用导致代码难以维护。

### 3.3.5 tsconfig.json

`tsconfig.json` 是 TypeScript 编译器的配置文件。

**顶层配置项**：
- `compileOnSave`：是否在文件保存时自动编译
- `include`：指定哪些目录/文件会被编译
- `exclude`：指定哪些目录/文件不会被编译
- `compilerOptions`：详细的编译规则（重中之重）

**compilerOptions 主要属性**：
- `target`：编译后的 ES 版本（ES3、ES5、ES6、ESNEXT）
- `module`：编译后的模块标准（CommonJS、ES6）
- `baseUrl`：模块的基本路径
- `paths`：基于 baseUrl 的模块路径
- `allowJs`：是否允许编译 JavaScript 文件
- `checkJs`：是否检查和报告 JavaScript 文件中的问题
- `sourceMap`：是否生成 `.map` 文件
- `strictNullChecks`：是否严格检查 null 和 undefined

**baseUrl + paths 配置路径别名**：

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  }
}
```
